# How the AppKit frontend presents each widget class of app/ that paints
# itself (docs/native-macos-ui.md, Coverage). The generic bridge
# (renderWidget, NativeDialogs.mm) maps Qt's own controls to AppKit ones and
# shows a widget it does not know only through its children: a widget's own
# painting is lost unless its line here says how it is shown. The ctest
# repo.native-coverage (tools/native-coverage) checks the list.
#
# One line per class: Class status detail
#   native SYMBOL    an AppKit view presents it; SYMBOL is that view's code
#                    in the AppKit frontend (app/platform/macos,
#                    app/MainWindowNative.cpp)
#   replaced SYMBOL  the Qt frontend's own chrome; the AppKit frontend shows
#                    SYMBOL in its place
#   shared REASON    Qt draws it in both frontends: the OCCT view and what
#                    is drawn over it
#   pending REASON   the AppKit frontend does not show it yet; none may be
#                    left when AppKit becomes the only macOS frontend
# The native UI tests fail when the bridge logs a widget it cannot present
# ("Native presenter: unpresented widget"), unless its class is pending here.
